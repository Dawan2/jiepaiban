## 1. 背景与问题

AI 短剧（竖屏、单集 1–3 分钟、系列化连载）的生产正在从"作坊式手工出片"转向"工业化流水线"。当前痛点：

1. **剧本到分镜靠人肉拆解**：编剧交付的剧本无法结构化流转到分镜/提示词环节，信息在飞书文档、Excel、微信群之间流失。
2. **角色一致性无法保证**：跨镜头、跨集数的角色外观漂移是 AI 短剧最大的质量杀手；缺乏统一的角色资产库与提示词注入机制。
3. **生成过程不可管理**：Seedance API 调用散落在个人脚本里，无队列、无重试、无版本、无成本核算。
4. **审片与返工混乱**：导演/监制的修改意见靠截图 + 口头描述，无法定位到具体镜头版本。
5. **成片组装靠剪辑师手工**：镜头素材命名混乱，无法自动按节拍顺序组装或导出到剪辑工程。

**产品目标**：以"节拍板（Beat Board）"为核心中枢，打通 *剧本 → 节拍/分镜 → 提示词 → Seedance2.5 生成 → 审核 → 成片导出* 的全链路，使一个 3–5 人小组能稳定地实现日更单集产能。`[假设：产能目标待原 PRD 确认]`

## 2. 目标用户与角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 制片人/项目管理员 | 管理项目、预算、进度、成员 | 全局进度与成本可视 |
| 编剧 | 撰写/导入剧本，拆分集与场 | 结构化写作，改动可追溯 |
| 分镜师/导演 | 把场拆成节拍与镜头，定义视听语言 | 高效拆解，直观预览 |
| 提示词工程师/生成操作员 | 组装提示词、提交与管理生成任务 | 批量、可复用、可回滚 |
| 审片人（导演/监制/平台审核对接人） | 审看镜头与成片，给出意见 | 精准标注、版本对比 |
| 剪辑/后期 | 导出素材与工程文件，完成成片 | 素材规整、元数据完备 |

`[假设]` 角色划分依常见 AI 短剧团队配置推导；小团队中一人可兼多角色，权限模型需支持角色叠加。

## 3. 产品范围（Scope）

### 3.1 In Scope（本产品负责）

- 项目/剧集/单集的管理与进度看板
- 剧本编写、导入与结构化解析（集 → 场 → 节拍）
- 角色资产库与角色一致性机制（参考图、主体参考、种子/风格锁定）
- 节拍板/分镜编辑（本产品的核心中枢视图）
- 提示词模板与组装、Seedance2.5 生成任务管线（队列、批量、重试、版本、成本）
- 镜头级与成片级审核工作流（批注、状态机、版本对比）
- 导出（素材打包、时间线工程文件、平台交付规格）
- 多人协作（权限、评论、通知、操作日志）

### 3.2 Out of Scope（明确不做）

- 通用视频剪辑器（只做粗剪时间线与导出，精剪交给剪映/PR/达芬奇）
- 配音/TTS、BGM 生成（P2 可作为集成点，首期不做）`[假设]`
- 短剧发行、投流、数据分析
- Seedance 之外的生成模型适配（架构上预留 Provider 抽象，但首期只对接 Seedance2.5）`[假设]`

## 4. 核心概念与领域模型

```
Project(项目/剧)
 └── Episode(集)
      └── Scene(场)
           └── Beat(节拍)               ← 叙事最小单元：一个情绪/信息转折
                └── Shot(镜头)          ← 生成最小单元：一次 Seedance 生成任务的目标
                     └── Take(版本/条)  ← 一次生成产出的一个候选结果
Character(角色) ──关联──> Beat/Shot（出场角色，驱动一致性注入）
AssetPack(角色资产包)：参考图集、主体参考(subject reference)、外观描述词、负向词、种子
PromptTemplate(提示词模板)：项目级/全局级，含变量占位符
GenerationJob(生成任务)：Shot × 参数 → 提交 Seedance2.5 → 产出 Take
Review(审核单)：针对 Take 或 Episode 成片的批注与结论
Export(导出任务)：素材包 / 时间线工程 / 成片视频
```

`[假设]` "节拍板"指以 Beat 为行、以状态/镜头为列的看板式中枢视图；Beat 与 Shot 分层（一个节拍可含多个镜头）。若原 PRD 将节拍与镜头合一，模型可退化为 Beat=Shot。

## 5. 功能需求（按模块）

### 5.1 模块 A：项目管理

- A1 创建/编辑/归档项目；项目属性：名称、题材标签、画幅（默认 9:16 竖屏 `[假设]`）、目标单集时长、封面。
- A2 剧集结构管理：项目下建集（Episode），支持排序、批量创建（如"第 1–80 集"占位）。
- A3 项目看板：按集展示状态（剧本中/分镜中/生成中/审核中/已导出），显示完成度与阻塞项。
- A4 成本与配额：项目级 Seedance 调用量、预估费用统计；可设预算告警阈值。
- A5 项目模板：从既有项目复制结构与模板（提示词模板、角色库、导出预设）。

### 5.2 模块 B：剧本

- B1 剧本编辑器：按集编辑，支持"场景标题/动作描述/对白/旁白"结构化段落。
- B2 剧本导入：粘贴纯文本或上传 docx/txt，自动解析为 场 → 节拍 草稿（规则 + LLM 辅助解析 `[假设]`），解析结果可人工修正。
- B3 版本管理：剧本每次保存生成版本，可 diff、可回滚；剧本改动能标记受影响的下游节拍。
- B4 剧本与节拍双向链接：从节拍可回看对应剧本原文段落。

### 5.3 模块 C：角色一致性（AI 短剧质量生命线）

- C1 角色卡：姓名、人设、外观结构化描述（发型/服装/年龄/体貌）、外观描述词（prompt 片段）、负向词。
- C2 角色资产包：上传/生成参考图集（多角度、多表情），指定 1–N 张为 Seedance **主体参考图（subject/character reference）**`[假设：Seedance2.5 支持图像参考输入]`；支持按"造型"（换装/换发型）建立子资产包。
- C3 一致性注入：镜头生成时，依据该镜头出场角色自动注入其参考图 + 外观描述词 + 负向词；多角色同框时按角色权重合成。
- C4 一致性校验（P1）：对生成结果做人脸/主体相似度打分，低于阈值自动标记"疑似角色漂移"。
- C5 角色资产版本化：换造型/换演员参考后旧版本可查，历史镜头保留生成时所用资产快照。

### 5.4 模块 D：分镜 / 节拍板（核心中枢）

- D1 节拍板视图：以场为分组，节拍为卡片；卡片显示：节拍序号、剧情摘要、出场角色、时长预估、状态、首选 Take 缩略图。
- D2 镜头编辑：节拍下建镜头，字段包括：景别（远/全/中/近/特）、机位/运镜（推拉摇移/固定/手持）、时长（秒）、画面描述、对白/音效备注、出场角色多选、情绪标签。
- D3 拖拽排序：节拍与镜头可拖拽调整顺序，顺序即成片时间线顺序。
- D4 提示词卡：每个镜头有"最终提示词"面板 = 模板 + 画面描述 + 角色注入 + 全局风格词，可手动覆写并保留组装痕迹。
- D5 节拍板总览导出：可打印/导出为 PDF 分镜表（P2）。
- D6 时长汇总：实时汇总本集镜头时长，对照目标单集时长给出提示。

### 5.5 模块 E：生成管线（Seedance2.5）

- E1 Provider 接入：对接 Seedance2.5 API（文生视频、图生视频、首尾帧、主体参考 `[假设：具体能力集以官方 API 文档为准]`）；密钥项目级配置。
- E2 任务队列：镜头提交后进入队列；支持并发上限、优先级、暂停/恢复；失败自动重试（可配次数）+ 死信区人工处理。
- E3 批量提交：按场/按集一键批量提交所有"就绪"镜头；支持每镜头 N 条候选（batch takes）。
- E4 参数管理：分辨率、时长、帧率、种子、运动强度等参数有项目级默认值，镜头级可覆写。
- E5 版本（Take）管理：每次生成产出 Take，含视频文件、缩略图、完整参数快照、提示词快照、成本；可标记"首选 Take"。
- E6 成本核算：任务级记录 token/时长计费，汇总到集与项目（对接 A4）。
- E7 失败诊断：区分内容审核拒绝 / 参数错误 / 限流 / 服务异常，给出可行动的错误信息。
- E8 Webhook/轮询兼容：生成完成后自动回填结果，节拍板卡片实时刷新。

### 5.6 模块 F：审核

- F1 镜头级审核：审片人对 Take 标记 通过/驳回/待定；驳回必填原因（可选标签：角色漂移/画面质量/不符剧本/审核风险）。
- F2 帧级批注：可在视频某一时间点截帧 + 画框 + 文字批注，批注与 Take 版本绑定。
- F3 版本对比：同镜头多个 Take 并排播放对比。
- F4 集级审片：按节拍顺序连播首选 Take（粗剪预览），整集给出审核结论。
- F5 状态机：镜头状态 = 草稿 → 待生成 → 生成中 → 待审 → 通过/驳回；驳回自动回到"待生成"并保留意见上下文。
- F6 合规预检（P2）：提示词与产出物的平台合规风险提示。

### 5.7 模块 G：导出

- G1 素材包导出：按规范命名（`项目_集_场_节拍_镜头_take` `[假设]`）打包下载已通过镜头，附 CSV/JSON 元数据清单。
- G2 时间线导出：生成剪辑工程交换文件（首期：剪映草稿或 FCPXML/EDL 其一 `[假设：优先级待确认]`），镜头按节拍顺序排列。
- G3 成片直出（P1）：服务端按顺序拼接首选 Take，输出 MP4（含转场硬切、可选字幕烧录 P2）。
- G4 交付预设：平台预设（抖音/快手/微信视频号）分辨率码率封装参数。
- G5 导出记录：每次导出留档（内容清单、操作人、时间），支持重新下载。

### 5.8 模块 H：协作

- H1 成员与角色权限：Owner/管理员/编辑者/审片人/只读；模块级权限（如编剧不可改生成参数 `[假设]`）。
- H2 评论与@提醒：节拍、镜头、Take、剧本段落均可评论，@成员触发通知。
- H3 通知中心：生成完成、审核结论、@提及、预算告警；站内 + 可选 webhook（飞书/企微 P2）。
- H4 操作日志：关键操作（删除、状态变更、导出、参数修改）可审计。
- H5 并发编辑保护：同一镜头编辑加锁或乐观合并提示，防止互相覆盖。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 节拍板 200+ 镜头/集流畅渲染（虚拟滚动）；生成状态刷新延迟 < 5s |
| 可靠性 | 生成任务持久化，服务重启不丢任务；素材对象存储 + 元数据库双写一致 |
| 成本安全 | 预算硬顶：超预算阻断批量提交（可管理员放行） |
| 安全 | API Key 服务端加密存储；素材访问走签名 URL；项目级数据隔离 |
| 合规 | 生成内容留存提示词与参数快照备查；平台送审素材可溯源 |
| 可扩展 | 生成 Provider 抽象层，未来接入其他模型无需改动上游模块 |

## 7. 技术架构建议（P3 槽位职责）

`[假设]` 原 PRD 未见技术选型，以下为建议方案，供 Wave 2 实现槽位参考：

- **前端**：React + TypeScript；节拍板用虚拟化看板组件；视频预览用 HLS/MP4 原生播放。
- **后端**：单体优先（Node.js/NestJS 或 Python/FastAPI），模块化边界与领域模型对齐（project/script/character/board/pipeline/review/export/collab）。
- **任务管线**：Redis 队列（BullMQ/Celery）承载 GenerationJob；worker 独立进程，支持水平扩展与限流。
- **存储**：PostgreSQL（元数据）+ S3 兼容对象存储（参考图/视频/导出包）。
- **实时性**：WebSocket/SSE 推送任务状态与协作事件。
- **Seedance 接入**：`providers/seedance` 适配层封装鉴权、限流、错误归类、成本换算；接口能力以火山引擎官方文档为准，联调前先做 API 能力探测 spike（见 backlog T-E0）。

## 8. 里程碑（与优先级对应）

- **M1（P0）最小工业闭环**：项目 → 剧本录入 → 节拍/镜头编辑 → 提示词组装 + 角色注入 → Seedance 单/批量生成 → 镜头审核 → 素材包导出。单人可用即达标。
- **M2（P1）提效与质量**：批量管线强化、一致性校验、版本对比、集级粗剪预览、成片直出、多人协作权限。
- **M3（P2）规模化**：项目模板、分镜表导出、合规预检、外部通知集成、多 Provider。

## 9. 风险与开放问题

1. **原 PRD 缺失**（最高风险）：本骨架所有 `[假设]` 项需在拿到 PDF 后逐一核对，尤其是：节拍与镜头的层级关系、Seedance2.5 实际能力集、导出目标格式、产能指标。
2. Seedance2.5 API 的主体参考/首尾帧等能力与配额未经验证 → P0 前置 spike（T-E0）。
3. 角色一致性天花板取决于模型能力，产品层只能"注入 + 校验 + 重roll"，需管理用户预期。
4. 内容合规：短剧题材（如伦理、擦边）易触发模型侧审核拒绝，需在错误诊断与提示词工程上留操作空间。

## 10. 成功指标（North Star 候选）

- 单集从剧本定稿到素材包导出的中位时长 ≤ 1 个工作日 `[假设]`
- 镜头一次通过率（首个 Take 即被采纳）≥ 40%，随模板与资产库沉淀持续上升
- 因角色漂移驳回的镜头占比 ≤ 15%
- 生成失败任务的自动恢复率 ≥ 90%
