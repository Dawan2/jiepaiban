# Backlog 与验收标准：Seedance2.5 AI 短剧节拍板工业化生产工具

> 配套 PRD：[`prd-seedance-tool.md`](./prd-seedance-tool.md)（骨架版，原始 PDF 缺失，`[假设]` 项待核对）
>
> 优先级定义：
> - **P0**：最小工业闭环（M1）必需，缺一不可上线
> - **P1**：显著提效/保质，M2 交付
> - **P2**：规模化与锦上添花，M3 交付
>
> 任务编号规则：`T-<模块字母><序号>`，模块字母与 PRD 第 5 节对应（A 项目 / B 剧本 / C 角色 / D 节拍板 / E 生成管线 / F 审核 / G 导出 / H 协作），`T-X*` 为跨模块基建。

---

## 0. 跨模块基建（P0 前置）

### T-X1 工程脚手架与领域模型落库 — **P0**
**用户故事**：作为开发团队，我需要初始化前后端工程与数据库 Schema（Project/Episode/Scene/Beat/Shot/Take/Character/PromptTemplate/GenerationJob），以便所有功能模块有统一地基。

**验收标准**
- Given 全新克隆的仓库，When 按 README 执行安装与启动命令，Then 前端与后端服务本地可运行且健康检查通过。
- Given 空数据库，When 执行迁移脚本，Then PRD 第 4 节领域模型全部建表，外键与级联规则齐备。

### T-X2 账号与登录 — **P0**
**用户故事**：作为使用者，我要能注册/登录，以便我的项目数据被隔离与保护。

**验收标准**
- Given 未登录用户，When 访问任意项目页面，Then 被重定向到登录页。
- Given 用户 A 已登录，When 尝试访问用户 B 的项目 ID，Then 返回 403 且不泄露项目存在性。

### T-E0 Seedance2.5 API 能力探测 spike — **P0（最优先，阻塞 C/E 模块设计定稿）**
**用户故事**：作为架构师，我需要验证 Seedance2.5 的文生视频/图生视频/主体参考/首尾帧能力、参数域、限流与计费，以便生成管线与角色一致性方案不建立在假设上。

**验收标准**
- Given 有效 API Key，When 分别调用各候选能力，Then 产出一份 `docs/spikes/seedance-api.md`，记录每项能力可用性、参数上下限、错误码分类与单位成本。
- Given spike 结论，When 与 PRD `[假设]` 项对照，Then 更新 PRD 中 C2/C3/E1/E4 的假设标注为已确认或已修正。

## 1. 模块 A：项目管理

### T-A1 项目 CRUD 与属性 — **P0**
**用户故事**：作为制片人，我要创建项目并设置画幅、目标单集时长，以便团队在统一规格下生产。

**验收标准**
- Given 已登录用户，When 填写名称并选择画幅（9:16/16:9/1:1）创建项目，Then 项目出现在列表且属性正确保存。
- Given 已有项目，When 归档它，Then 项目从默认列表隐藏但可在"已归档"中查看与还原。

### T-A2 剧集结构管理 — **P0**
**用户故事**：作为制片人，我要在项目下批量创建并排序剧集，以便承接连载排期。

**验收标准**
- Given 一个项目，When 批量创建"第 1–20 集"，Then 生成 20 个按序号排列的空集。
- Given 多个集，When 拖拽调整顺序，Then 刷新后顺序保持。

### T-A3 项目进度看板 — **P1**
**用户故事**：作为制片人，我要看到每集所处阶段与完成度，以便识别产线阻塞。

**验收标准**
- Given 各集处于不同阶段，When 打开项目看板，Then 每集显示状态徽标（剧本中/分镜中/生成中/审核中/已导出）与镜头完成率百分比。
- Given 某集存在驳回未处理镜头，When 查看看板，Then 该集显示阻塞标记与阻塞数量。

### T-A4 成本统计与预算告警 — **P1**
**用户故事**：作为制片人，我要看到项目累计生成成本并设置预算，以便控制烧钱速度。

**验收标准**
- Given 项目已产生生成任务，When 打开成本页，Then 显示按集聚合的调用次数、时长与费用，与任务级明细之和一致。
- Given 预算阈值 80% 已设定，When 累计费用越过阈值，Then 管理员收到通知；When 费用达 100%，Then 批量提交被阻断且提示可由管理员放行。

### T-A5 项目模板复制 — **P2**
**用户故事**：作为制片人，我要从旧项目复制提示词模板、角色库与导出预设，以便新剧快速开机。

**验收标准**
- Given 一个既有项目，When 选择"由此创建新项目"并勾选复制项，Then 新项目含所选资产副本且与源项目互不影响。

## 2. 模块 B：剧本

### T-B1 结构化剧本编辑器 — **P0**
**用户故事**：作为编剧，我要按"场景标题/动作/对白/旁白"结构撰写单集剧本，以便下游可机读拆解。

**验收标准**
- Given 一个集，When 依次添加场景标题与对白段落并保存，Then 刷新后结构与内容完整保留。
- Given 编辑中的剧本，When 断网 10 秒后恢复，Then 本地未保存内容不丢失并提示重新保存。

### T-B2 剧本导入与自动拆解 — **P1**
**用户故事**：作为编剧，我要粘贴既有剧本文本并自动解析为场与节拍草稿，以便存量剧本快速迁移。

**验收标准**
- Given 一段含"第X场/内景/外景"标记的剧本文本，When 执行导入解析，Then 场景边界识别正确率在验收样本集（≥10 个真实剧本）上 ≥ 90%，解析结果以草稿态呈现。
- Given 解析草稿，When 人工合并/拆分/修正任意节拍，Then 修正结果覆盖机器结果并进入正式节拍板。

### T-B3 剧本版本与 diff — **P1**
**用户故事**：作为编剧，我要查看剧本历史版本差异并回滚，以便改稿可追溯。

**验收标准**
- Given 剧本已保存 3 个版本，When 选择 v1 与 v3 对比，Then 增删改段落以高亮 diff 呈现。
- Given 历史版本 v2，When 回滚到 v2，Then 生成新版本 v4（内容等于 v2），不破坏历史链。

### T-B4 剧本改动影响标记 — **P2**
**用户故事**：作为导演，我要在剧本修改后看到受影响的节拍被标记"剧本已变更"，以便决定是否重拆重生成。

**验收标准**
- Given 节拍已链接剧本段落，When 该段落文字被修改并保存，Then 对应节拍卡片出现"剧本已变更"标记，确认后标记清除。

## 3. 模块 C：角色一致性

### T-C1 角色卡管理 — **P0**
**用户故事**：作为导演，我要为每个角色建立含外观描述词与负向词的角色卡，以便生成时统一注入。

**验收标准**
- Given 一个项目，When 创建角色并填写外观结构化字段与 prompt 片段，Then 角色出现在角色库且可被镜头引用。
- Given 已被 5 个镜头引用的角色，When 尝试删除，Then 系统阻止并列出引用位置（支持改为"停用"）。

### T-C2 角色参考图资产包 — **P0**
**用户故事**：作为导演，我要为角色上传多角度参考图并指定主体参考图，以便 Seedance 生成时锁定角色外观。

**验收标准**
- Given 一个角色，When 上传 ≥3 张参考图并指定其中 1 张为主体参考，Then 资产包保存成功且主体参考在角色卡显著展示。
- Given 角色需要换装，When 创建"造型 B"子资产包，Then 镜头可在造型 A/B 间选择，互不覆盖。

### T-C3 生成时角色自动注入 — **P0**
**用户故事**：作为生成操作员，我要在提交镜头生成时系统按出场角色自动注入参考图与描述词，以便不靠人工拷贝提示词保持一致性。

**验收标准**
- Given 镜头关联了角色"林晚"（含主体参考图与描述词），When 打开该镜头的最终提示词面板，Then 面板显示模板 + 画面描述 + 林晚描述词的组装结果及来源标注，且提交的 API 请求携带其主体参考图。
- Given 双角色同框镜头，When 提交生成，Then 两个角色的参考与描述均被注入（若 T-E0 证实 API 仅支持单主体参考，Then 系统提示能力上限并允许指定主参考角色）。

### T-C4 角色一致性自动校验 — **P1**
**用户故事**：作为审片人，我要系统对生成结果自动做角色相似度打分，以便快速过滤角色漂移的废片。

**验收标准**
- Given 一个含角色主体参考的已完成 Take，When 校验任务运行完成，Then Take 上显示相似度分数；低于项目阈值时标记"疑似漂移"。
- Given 被标记"疑似漂移"的 Take，When 审片人人工判定为正常，Then 可一键解除标记并计入阈值调优数据。

### T-C5 角色资产版本化 — **P1**
**用户故事**：作为导演，我要角色资产更新后历史镜头仍保留生成当时的资产快照，以便追溯与复现。

**验收标准**
- Given 镜头 S 在资产 v1 下生成了 Take，When 角色资产升级到 v2，Then Take 详情仍显示 v1 快照；When 重新生成 S，Then 新 Take 使用 v2。

## 4. 模块 D：分镜 / 节拍板

### T-D1 节拍板核心视图 — **P0**
**用户故事**：作为导演，我要以场分组、节拍为卡片的中枢视图查看整集，以便一屏掌握剧情与生产状态。

**验收标准**
- Given 一个含 5 场 30 节拍的集，When 打开节拍板，Then 按场分组渲染全部节拍卡片，卡片显示序号、摘要、出场角色、状态与首选 Take 缩略图。
- Given 200 个镜头的集，When 滚动浏览节拍板，Then 滚动流畅（虚拟滚动，无整页卡顿）。

### T-D2 节拍与镜头 CRUD + 字段编辑 — **P0**
**用户故事**：作为分镜师，我要在节拍下创建镜头并编辑景别、运镜、时长、画面描述与出场角色，以便完成分镜拆解。

**验收标准**
- Given 一个节拍，When 添加镜头并填写景别=近景、时长=4s、勾选出场角色，Then 保存后字段完整回显。
- Given 一个镜头，When 删除它，Then 需二次确认；若其下存在已生成 Take，Then 提示 Take 数量并要求显式确认。

### T-D3 拖拽排序 — **P0**
**用户故事**：作为导演，我要拖拽调整节拍与镜头顺序，以便顺序即成片时间线。

**验收标准**
- Given 节拍板上的节拍 3 与节拍 5，When 将节拍 5 拖到节拍 3 之前，Then 序号自动重排且刷新后保持；导出顺序同步更新。
- Given 两名成员同时拖拽同一场的节拍，When 冲突发生，Then 后提交者收到刷新提示而非静默覆盖。

### T-D4 提示词卡与手动覆写 — **P0**
**用户故事**：作为提示词工程师，我要查看每个镜头由"模板+画面描述+角色注入+风格词"组装的最终提示词并可手动覆写，以便兼顾自动化与精修。

**验收标准**
- Given 一个字段齐备的镜头，When 打开提示词卡，Then 显示组装后的完整提示词，各片段来源（模板/角色/画面描述）可辨识。
- Given 手动覆写了提示词的镜头，When 上游模板或角色描述词变更，Then 覆写内容不被自动改写，但出现"上游已变更"提示可一键重新组装。

### T-D5 提示词模板管理 — **P0**
**用户故事**：作为提示词工程师，我要维护项目级提示词模板（含变量占位符与全局风格词），以便全剧风格统一。

**验收标准**
- Given 项目模板含占位符 `{画面描述}` `{角色}` `{景别}`，When 镜头组装提示词，Then 占位符被对应字段正确替换，空字段占位符被安全省略。
- Given 模板更新，When 查看未覆写镜头的提示词卡，Then 自动反映新模板。

### T-D6 时长汇总提示 — **P1**
**用户故事**：作为导演，我要实时看到全集镜头时长合计与目标时长的对比，以便控制单集节奏。

**验收标准**
- Given 目标单集时长 120s，When 镜头时长合计为 95s，Then 节拍板顶部显示 95/120s 及缺口提示；合计超出 120s 时显示超量警示。

### T-D7 分镜表 PDF 导出 — **P2**
**用户故事**：作为制片人，我要把节拍板导出为可打印分镜表，以便线下评审或对外沟通。

**验收标准**
- Given 一个完整分镜的集，When 导出分镜表 PDF，Then 按场-节拍-镜头顺序列出关键字段与首选 Take 缩略图。

## 5. 模块 E：生成管线（Seedance2.5）

### T-E1 Seedance Provider 适配层 — **P0**
**用户故事**：作为系统，我需要一个封装鉴权、参数映射、限流与错误归类的 Seedance2.5 适配层，以便上游模块不感知 API 细节。

**验收标准**
- Given 项目配置了有效 API Key，When 通过适配层提交一次文生视频请求，Then 返回任务句柄并最终取回视频结果。
- Given API 返回限流/内容拒绝/参数错误/服务异常四类错误，When 适配层处理，Then 各自映射为独立错误类型且带有可读中文说明。
- Given 无效 API Key，When 提交任务，Then 得到明确的鉴权失败提示而非笼统报错。

### T-E2 生成任务队列 — **P0**
**用户故事**：作为生成操作员，我要提交的任务进入持久化队列并自动重试，以便夜间批量跑片无人值守。

**验收标准**
- Given 队列中有 10 个任务且并发上限为 3，When 队列运行，Then 同时进行的 API 调用不超过 3 个，全部任务最终完成。
- Given 一个任务因限流失败，When 自动重试（指数退避，默认 3 次），Then 重试成功后正常回填；3 次仍失败进入死信区待人工处理。
- Given 队列中有等待任务，When 后端服务重启，Then 任务不丢失并继续执行。

### T-E3 单镜头提交与状态回显 — **P0**
**用户故事**：作为生成操作员，我要在镜头卡上一键提交生成并看到实时状态，以便边拆边试。

**验收标准**
- Given 一个提示词就绪的镜头，When 点击"生成"，Then 卡片状态依次经历 排队中→生成中→完成，无需手动刷新（延迟 ≤5s）。
- Given 生成完成，When 查看镜头，Then 新 Take 的视频可在线播放，缩略图出现在卡片上。

### T-E4 批量提交 — **P0**
**用户故事**：作为生成操作员，我要按场或按集批量提交所有就绪镜头（每镜头可选 N 条候选），以便一次跑完整集。

**验收标准**
- Given 一个含 20 个就绪镜头的场，When 选择"批量生成 ×2 候选"，Then 创建 40 个任务入队，进度面板显示完成/失败/进行中计数。
- Given 批量中的部分镜头提示词为空，When 提交，Then 这些镜头被跳过并在结果报告中列出原因。

### T-E5 Take 版本管理与首选标记 — **P0**
**用户故事**：作为导演，我要每个镜头的多次生成结果都保留为 Take 并可标记首选，以便择优组装成片。

**验收标准**
- Given 一个镜头有 3 个 Take，When 打开镜头详情，Then 3 个 Take 按时间排列，各自附完整参数与提示词快照。
- Given 标记 Take#2 为首选，When 查看节拍板与导出预览，Then 缩略图与成片顺位均使用 Take#2。

### T-E6 参数默认值与镜头级覆写 — **P1**
**用户故事**：作为生成操作员，我要项目级默认生成参数与镜头级覆写，以便统一规格又保留灵活性。

**验收标准**
- Given 项目默认分辨率 1080×1920、时长 5s，When 新镜头提交且未覆写，Then 请求采用默认值。
- Given 镜头覆写时长为 8s，When 提交，Then 请求采用 8s 且 Take 快照记录覆写来源。

### T-E7 成本记录 — **P1**
**用户故事**：作为制片人，我要每个任务记录成本并向上聚合，以便与预算模块联动。

**验收标准**
- Given 一个完成的生成任务，When 查看任务详情，Then 显示按 T-E0 探明计费规则换算的费用；集/项目聚合值等于明细和（对接 T-A4）。

### T-E8 失败诊断面板 — **P1**
**用户故事**：作为生成操作员，我要在死信区看到失败任务的归类原因与建议动作，以便快速修复重投。

**验收标准**
- Given 死信区有内容审核拒绝的任务，When 查看详情，Then 显示"内容拒绝"归类、原始错误与"修改提示词后重投"入口。
- Given 修改提示词后重投，When 任务成功，Then 新 Take 正常挂载到原镜头。

## 6. 模块 F：审核

### T-F1 镜头级审核状态机 — **P0**
**用户故事**：作为审片人，我要对 Take 给出通过/驳回（附原因），驳回自动使镜头回到待生成，以便返工路径清晰。

**验收标准**
- Given 一个待审 Take，When 标记通过，Then 镜头状态变为"通过"且节拍板卡片同步。
- Given 一个待审 Take，When 驳回且未填原因，Then 提交被阻止；填写原因（可选标签：角色漂移/画面质量/不符剧本/审核风险）后，Then 镜头回到"待生成"且原因在镜头上下文中可见。

### T-F2 帧级批注 — **P1**
**用户故事**：作为审片人，我要在视频具体时间点截帧画框写意见，以便返工方知道改哪里。

**验收标准**
- Given 播放中的 Take，When 在 00:02.5 处暂停并框选画面区域添加批注"手部畸变"，Then 批注锚定该时间点与区域，列表点击可跳转定位。
- Given Take 被驳回重生成，When 查看新 Take，Then 旧批注保留在旧 Take 上，不污染新版本。

### T-F3 Take 并排对比 — **P1**
**用户故事**：作为导演，我要同镜头两个 Take 并排同步播放，以便快速择优。

**验收标准**
- Given 一个镜头的 Take#1 与 Take#3，When 进入对比模式并播放，Then 两视频同步起播，可在对比视图直接标记首选。

### T-F4 集级粗剪连播审片 — **P1**
**用户故事**：作为监制，我要按节拍顺序连播全集首选 Take，以便整体审看节奏与连贯性。

**验收标准**
- Given 全集镜头均有首选 Take，When 启动连播，Then 按节拍板顺序无缝连播，播放器显示当前镜头编号，可暂停跳到该镜头详情。
- Given 部分镜头缺首选 Take，When 启动连播，Then 缺失位显示占位卡并在侧栏列出缺口清单。

### T-F5 平台合规预检 — **P2**
**用户故事**：作为制片人，我要提示词与产出物的合规风险提示，以便降低平台下架风险。

**验收标准**
- Given 提示词含预置敏感词库命中项，When 提交生成前，Then 显示风险提示但不强制阻断（管理员可配置为阻断）。

## 7. 模块 G：导出

### T-G1 素材包导出 — **P0**
**用户故事**：作为剪辑师，我要一键导出全集已通过镜头的规范命名素材包与元数据清单，以便直接进入精剪。

**验收标准**
- Given 一个集有 25 个已通过镜头，When 执行素材包导出，Then 得到 zip：视频按 `项目_集_场_节拍_镜头_take` 命名，附含时长/提示词/参数/顺序的 CSV 与 JSON 清单。
- Given 有 2 个镜头未通过审核，When 导出，Then 默认仅含已通过镜头，报告中列出缺口；可显式选择"包含未通过"。

### T-G2 时间线工程导出 — **P1**
**用户故事**：作为剪辑师，我要导出按节拍顺序排列的剪辑工程文件，以便在剪辑软件中免手工排序。

**验收标准**
- Given 全集首选 Take 齐备，When 导出时间线（首期目标格式以 T-E0 后的技术评审定稿：剪映草稿或 FCPXML），Then 在目标软件中打开后镜头顺序、时长与节拍板一致。

### T-G3 成片直出 MP4 — **P1**
**用户故事**：作为制片人，我要服务端直接拼接首选 Take 输出成片 MP4，以便快速出样片。

**验收标准**
- Given 全集首选 Take 齐备，When 选择平台预设"抖音 1080×1920"并导出，Then 产出可播放 MP4，分辨率码率符合预设，镜头顺序与节拍板一致。
- Given 导出任务进行中，When 查看导出中心，Then 显示进度；完成后保留下载记录（操作人/时间/内容清单）。

### T-G4 交付平台预设管理 — **P2**
**用户故事**：作为管理员，我要维护平台交付预设（分辨率/码率/封装），以便多平台分发规格统一。

**验收标准**
- Given 新建预设"快手竖屏"，When 在导出时选择它，Then 输出参数与预设一致；预设修改不影响历史导出记录。

## 8. 模块 H：协作

### T-H1 成员邀请与角色权限 — **P0**
**用户故事**：作为项目管理员，我要邀请成员并赋予 Owner/管理员/编辑者/审片人/只读角色，以便分工协作且权限受控。

**验收标准**
- Given 管理员生成邀请，When 新成员接受，Then 成员以指定角色进入项目。
- Given 只读成员，When 尝试编辑镜头或提交生成，Then 操作不可见或被 403 拒绝。
- Given 审片人角色，When 进入系统，Then 可执行审核操作但不能修改分镜与生成参数。

### T-H2 评论与@提醒 — **P1**
**用户故事**：作为团队成员，我要在节拍/镜头/Take 上评论并@同事，以便沟通留在上下文里。

**验收标准**
- Given 镜头详情页，When 发表评论并@某成员，Then 评论落在该镜头上下文，被@者收到通知，点击直达该镜头。

### T-H3 通知中心 — **P1**
**用户故事**：作为生成操作员，我要在站内收到批量生成完成、审核结论与预算告警通知，以便及时跟进。

**验收标准**
- Given 一次批量生成完成，When 打开通知中心，Then 有汇总通知（成功/失败计数）并可跳转到对应集。
- Given 通知未读，When 顶栏查看，Then 显示未读计数，已读后消除。

### T-H4 操作审计日志 — **P1**
**用户故事**：作为管理员，我要查询删除、状态变更、导出、参数修改等关键操作日志，以便追责与排障。

**验收标准**
- Given 成员删除了一个节拍，When 管理员查询日志，Then 可见操作人、时间、对象与操作前摘要；日志不可被普通成员篡改或删除。

### T-H5 并发编辑保护 — **P2**
**用户故事**：作为分镜师，我要在他人正在编辑同一镜头时得到提示，以便避免互相覆盖。

**验收标准**
- Given 成员 A 正在编辑镜头 S，When 成员 B 打开 S 的编辑态，Then B 看到"A 正在编辑"提示；When B 仍保存且与 A 冲突，Then 后保存者收到冲突提示并可查看双方差异。

### T-H6 外部通知集成（飞书/企微 webhook） — **P2**
**用户故事**：作为团队，我要关键事件推送到飞书群，以便不开系统也能掌握产线动态。

**验收标准**
- Given 配置了飞书 webhook，When 批量生成完成或预算告警触发，Then 群内收到含跳转链接的消息卡片。

## 10. P0 依赖顺序（就绪度）

```
T-E0 (API spike) ──┐
T-X1 (脚手架/模型) ─┼─> T-X2 (登录) ─> T-A1/T-A2 (项目/集)
                    │        └─> T-B1 (剧本)  ─> T-D1/T-D2/T-D3 (节拍板)
                    │        └─> T-C1/T-C2 (角色卡/资产)
                    └─> T-E1 (适配层) ─> T-E2 (队列) ─> T-E3/T-E4 (提交)
T-D4/T-D5 (提示词) + T-C3 (角色注入) ─> T-E3
T-E5 (Take) ─> T-F1 (审核) ─> T-G1 (素材导出)
T-H1 (权限) 可与 T-A1 并行
```

**立即可动工（无内部依赖）的 P0 任务**：`T-E0`、`T-X1`。
其后第一波：`T-X2`、`T-E1`；第二波：`T-A1/T-A2`、`T-B1`、`T-C1/T-C2`、`T-D5`、`T-E2`。
