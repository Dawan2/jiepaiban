## 1. 产品定义（Product Definition）

**一句话定义：** 一个**只服务 Seedance 2.5**、以**剧情节拍**为唯一叙事单元的 AI 短剧创作工具。

| 维度 | 定义 |
| --- | --- |
| 模型绑定 | **Seedance 2.5 独占**（Seedance2.5-only）。不做多模型抽象层、不做模型选择器。 |
| 叙事内核 | 节拍驱动（beat-driven）。`1 Beat = 1 G = 1 节拍板 = 1 次 generate`。 |
| 内容形态 | 竖屏 AI 漫剧短剧，单集 **70–90s**。 |
| 生产链路 | 定节拍 → 定镜头组 → 填节拍帧 → AI 生成 → 后期合成。 |
| 交付物 | 5 段视频 + 组间衔接参数 + 成片记录（可导出飞书）。 |

### 1.1 产品主张（Positioning）

1. **把创作者从微观决策里解放出来**：组内运镜、剪辑点、时长微观分配全部交给 Seedance 2.5；人只做宏观情绪、宏观节奏与组间衔接。
2. **用结构代替灵感**：五节拍锁把"爆款结构"固化为不可变骨架，新建项目即得到可用结构。
3. **一板一次生成**：生产单元与叙事单元恒等，成本、进度、返工范围三者天然对齐。

### 1.2 明确不做（Non-Goals）

| 不做 | 原因（法源） |
| --- | --- |
| 多模型/模型选择 | 产品定位为 Seedance 2.5 独占 |
| 比 `beat` 更细的叙事编辑单元 | `METH-001 §3` 判定规则：粒度小于 beat 即废弃项 |
| 组内人工剪辑点 / 组内转场 | `METH-001 §9` R1 |
| 时间线轨道式剪辑器 | 与"板"为最小单元冲突，属废弃粒度 |
| 逐画面时长输入 | `METH-001 §3` 废弃项（per-shot duration） |
| 第四个一级页面 | `METH-001 §10.2`：页面只有三个 |

### 1.3 废弃项复述（Discard List，禁止实现）

以下四项在本产品中**不存在对应概念**，任何需求、UI、字段、导出格式均不得出现（术语引用见 `METH-002 §8` 禁用词表）：

| # | 废弃项 | 违规表现（禁止出现） |
| --- | --- | --- |
| D1 | 单画面 S 拆解 | `shot_list` 字段、`S1/S2/S3` 输入框 |
| D2 | 分镜 / 故事板（storyboard，**禁用词**） | 同名页面、同名导出模板、同名字段 |
| D3 | 单镜时长（per-shot duration，**禁用词**） | 每个画面一个 duration 输入框 |
| D4 | 手动逐画面转场 | 组内相邻画面之间的转场下拉框 |

## 2. 目标与成功指标（Goals & Metrics）

| 编号 | 目标 | 成功指标（V1.0 验收口径） |
| --- | --- | --- |
| G1 | 结构零成本 | 新建项目后 **0 次手动操作**即拥有 5 块锁定节拍板 |
| G2 | 单集产出效率 | 从新建到 5 段视频齐备，人工填写步骤 ≤ 5 板 × 4 槽位 + 帧文案 |
| G3 | Prompt 一致性 | 100% prompt 由组装器生成，槽位顺序 100% 一致，**转场词出现率 0%** |
| G4 | 结构合规率 | `len(beat_list) == 5`、宫格数匹配、单板 ≤ 30s 三项校验通过率 100% |
| G5 | 复用价值 | 复用项目创建耗时 ≤ 新建 + 1 次点击，且结构/参数 100% 继承、画面内容 100% 清空 |
| G6 | 协作交付 | 成片记录可一键导出飞书，字段完整率 100% |

## 3. 用户与场景（Users & Scenarios）

### 3.1 角色

| 角色 | 代号 | 关注点 | 在系统中的权责 |
| --- | --- | --- | --- |
| 短剧编剧 | `U-WRITER` | 结构是否成立、钩子是否够狠 | 填 5 板的情绪 / 剧情核心 / 节拍帧 |
| 短剧导演 | `U-DIRECTOR` | 宏观节奏、组间衔接 | 定镜头节奏描述、选组间衔接、验收成片 |
| 内容运营 | `U-OPS` | 批量产出与复用 | 复用项目、管理成片、导出飞书 |

> V1.0 不做多人权限模型，三个角色可由同一账号承担；角色区分用于需求归因，不用于权限设计。

### 3.2 核心场景

| # | 场景 | 触发 | 期望结果 |
| --- | --- | --- | --- |
| SC1 | 新剧本快速成型 | 有一个爆款梗，需要 90 秒内讲完 | 新建项目 → 直接在 5 块板上填内容 → 生成 |
| SC2 | 同结构换题材 | 上一集数据好，想换故事复刻结构 | 复用项目：结构与参数继承，画面内容清空 |
| SC3 | 单板返工 | 第 3 板生成结果不满意 | 只改第 3 板、只重生成第 3 板，其余 4 板不受影响 |
| SC4 | 后期合成 | 5 段视频齐备 | 拿到 5 段视频 + 组间衔接参数表，进入合成 |
| SC5 | 交付归档 | 成片完成 | 成片管理页登记 → 导出飞书 |

## 5. 核心规则（Core Rules，全局约束）

所有规则均为法源直接落地，编号用于下游追溯。

| 编号 | 规则 | 取值 | 法源 |
| --- | --- | --- | --- |
| `RULE-1` | 恒等式 | `1 Beat = 1 G = 1 节拍板 = 1 次 generate` | `METH-001 §1` |
| `RULE-2` | 五节拍锁 | 开篇钩子 → 矛盾建立 → 打压升级 → 反转蓄力 → 断集留客；恒为 5，不可增删改序 | `METH-001 §4` |
| `RULE-3` | 宫格锁 | B1–B4 = 3 宫格；B5 = 2 宫格；用户不可改 | `METH-001 §6`、R7 |
| `RULE-4` | 单板时长上限 | ≤ 30s（硬拦截） | R3 |
| `RULE-5` | 整集时长 | 70–90s（基准轴 88s，可整体伸缩） | `METH-001 §4` |
| `RULE-6` | 人机分工 | AI 管组内（运镜/剪辑点/时长微观）；人管组间（衔接/宏观情绪节奏） | `METH-001 §2`、R1/R2 |
| `RULE-7` | 帧序锁 | 节拍帧只按左→右读取与提交，无拖拽重排、无"主帧" | R4 |
| `RULE-8` | Prompt 公式 | `固定前缀 + 本段情绪 + 时长 + 镜头节奏 + 剧情核心`，顺序不可变 | `METH-001 §7.2` |
| `RULE-9` | 转场隔离 | 转场**永不进入** AI prompt | R8 |
| `RULE-10` | 生成 1:1 | 一块板一次调用；不拆、不合 | `METH-001 §1` |
| `RULE-11` | 无故事板 | 概念级禁止（见 §1.3 D2） | R6、L2 |
| `RULE-12` | 衔接枚举封闭 | 组间衔接取值只能落在封闭枚举内（见 §6.5） | `METH-002 §5` |

### 5.1 五节拍基准表（模板骨架，CANON）

| 板 | 节拍 | 镜头组 | 时间位 | 时长 | 宫格数 | 帧语义 | 组间衔接（本板 → 下一板） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| B1 | 开篇钩子 | G1 | 0–8s | 8s | 3 | 冲击 / 反应 / 环境 | 音频预接 |
| B2 | 矛盾建立 | G2 | 8–25s | 17s | 3 | 三帧递进 | 卡点硬切 |
| B3 | 打压升级 | G3 | 25–45s | 20s | 3 | 三帧递进 | 纯硬切（见 §12 `O-P2-1`） |
| B4 | 反转蓄力 | G4 | 45–70s | 25s | 3 | 三帧递进 | 卡点硬切 + BGM 升调 |
| B5 | 断集留客 | G5 | 70–88s | 18s | 2 | 两帧收束 | 无转场，黑屏截断 |

合计 88s / 5 次生成 / 14 个节拍帧（3+3+3+3+2）。

### 6.3 M3 Prompt 组装器（Prompt Assembler）

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| `FR-3-01` | 固定顺序组装 | P0 | 严格 `固定前缀 + 本段情绪 + 时长 + 镜头节奏 + 剧情核心`；组装器不得改序 |

| BGM 升调截断 | `BGM_PITCH_CUT` | 升调推情绪并截断（可作修饰叠加） | B4 → B5 |
| 黑屏断钩子 | `BLACK_CUT_HOOK` | 黑屏截断留悬念 | B5 集尾 |

枚举**封闭**；新增取值必须先改方法论，产品内不提供自定义输入。`METH-003 §8` 基准表中 B3→B4 的"纯硬切"未列入本枚举，处理口径见 §12 `O-P2-1`。

### 6.6 M6 成片管理（Final Cut Management）

## 7. 关键流程（Key Flows）

工作流阶段沿用 `METH-001 §5`：**定节拍 → 定镜头组 → 填节拍帧 → AI 生成 → 后期合成**（阶段 1–5）。

### 7.1 新建项目（Create Project）

```
项目列表 → 新建项目 → 输入项目名
      → 系统按模板实例化 beat_list[5]（顺序/语义/宫格数/时间位全部锁定）
      → 跳转核心编辑器，5 块板已就位（B1-B4 三宫格 / B5 两宫格）
```

约束：

1. 新建**必然**产生 5 块板，不存在"空项目"或"自选板数"。
2. `total_duration` 初始化为模板基准 88s；随板时长编辑实时重算。
3. `transition_rule` 按 §5.1 预置，用户可在枚举内改（B5 除外）。

### 7.2 复用项目（Reuse Project）

```
项目列表/编辑器 → 复用 → 生成新项目
   继承：beat_list 结构、节拍语义、宫格数、时间位与时长、ai_param 参数、transition_rule
   清空：frame_list 内的画面文案、prompt_final、video_url、生成状态
```

约束：

1. 复用是**结构与参数的复制 + 内容的清空**，不是"另存副本"。
2. 清空项一律回到空态，不保留上一集残留内容。
3. 复用产物仍受全部核心规则约束（仍是 5 板锁定结构）。

### 7.3 单板生成（Generate One Board）

```
板必填齐备 → 组装 prompt（≤200ms）→ 前置校验（时长/宫格/转场词）
   → 提交 1 次 Seedance 2.5 调用 → 排队 → 生成中 → 成功写 video_url / 失败可重试
```

### 7.4 后期合成与交付（Composite & Deliver）

```
5 板齐备 → 导出衔接总表（B1→B2 … B5→下一集）
   → 人工后期合成（衔接手法在此阶段应用）
   → 成片页登记成片 → 导出飞书
```

## 8. 数据模型（Data Model）— **beat 字段唯一来源**

> 本节是 `beat` 字段的**唯一权威定义**（`METH-001 §10.3` 指定）。其他文档只能引用，不得复制或扩写字段语义。

### 8.1 `project`（项目 / 集）

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `project_id` | `id` | 是 | 主键，不可变 | 项目唯一标识 |
| `name` | `string` | 是 | 1–60 字符 | 项目（集）名称 |
| `total_duration` | `number(seconds)` | 是 | **70–90** | 整集总时长；等于 5 板时长之和 |
| `beat_list` | `array<beat>` | 是 | **长度恒为 5**，顺序恒定 | 五块节拍板 |

约束：

- `len(beat_list) == 5` 由数据层拦截（R5）。
- `total_duration == Σ beat.duration`；越界（<70 或 >90）为警示，不阻断保存，阻断"可交付"标记。

### 8.2 `beat`（节拍板）

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `beat_id` | `id` | 是 | 主键 | 节拍板唯一标识 |
| `group_id` | `string` | 是 | `G1`–`G5`，与板序一一对应，只读 | 镜头组标识 |
| `beat_name` | `enum` | 是 | 开篇钩子 / 矛盾建立 / 打压升级 / 反转蓄力 / 断集留客，只读 | 节拍语义，锁定不可改 |
| `emotion` | `string` | 是 | 1–120 字符，**人填** | 本段宏观情绪定调；进 prompt 第 2 槽位 |
| `time_range` | `object` | 是 | `{ start, end }`，秒；`end > start` | 本板在整集中的时间位 |
| `frame_list` | `array<frame>` | 是 | 长度 = `frame_count`（B1–B4 = 3，B5 = 2）；**左→右顺序** | 节拍帧列表 |
| `ai_param` | `object` | 是 | 见 §8.4 | 交给 AI 的组内约束参数 |
| `transition_rule` | `object` | 是 | 见 §8.5 | 组间衔接（本板 → 下一板），**不进 prompt** |
| `prompt_final` | `string` | 否 | 只读，由组装器生成 | 最终 prompt 快照 |
| `video_url` | `string(url)` | 否 | 生成成功后写入 | 本板视频地址 |

派生字段（不独立存储，由上表推导）：

| 派生项 | 推导式 | 用途 |
| --- | --- | --- |
| `duration` | `time_range.end - time_range.start` | **≤ 30**（R3）；prompt 第 3 槽位 |
| `frame_count` | 板序推导：B1–B4 = 3，B5 = 2 | 宫格渲染与校验（R7） |
| `beat_index` | `beat_list` 下标 + 1（1–5） | 板序、与 `group_id` 绑定 |

### 8.3 `frame`（节拍帧）

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `frame_id` | `id` | 是 | 主键 | 帧唯一标识 |
| `index` | `int` | 是 | 1–3，**左→右**，只读 | 帧位；无重排入口（R4） |
| `semantic` | `enum` | 是 | `IMPACT` / `REACTION` / `ENV` / `PROGRESS` / `SUSPENSE` / `CUTOFF`，只读 | 帧语义占位；B1 用 冲击/反应/环境 |
| `content` | `string` | 是 | 1–200 字符，人填 | 该段内一个关键画面信息点 |

**禁止字段：** `frame` 下不得出现任何时长字段、转场字段、排序权重字段（分别触犯 D3、D4、R4）。

### 8.4 `ai_param`（组内约束参数）

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `camera_rhythm` | `string` | 是 | 1–120 字符 | 镜头节奏形容；**不得含刀数/逐画面时长**；prompt 第 4 槽位 |
| `plot_core` | `string` | 是 | 1–160 字符 | 一句话剧情推进；prompt 第 5 槽位 |
| `model` | `const` | 是 | 恒为 `seedance-2.5` | 模型固定，无选择项 |
| `aspect_ratio` | `enum` | 是 | 默认 `9:16` | 竖屏短剧 |
| `resolution` | `enum` | 是 | 默认 `8K` 档，与固定前缀一致 | 画质档位 |

**禁止字段：** `shot_list`、`cut_count`、`per_shot_duration`、`intra_transition` —— 均属废弃项，出现即违规。

### 8.5 `transition_rule`（组间衔接）

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `codes` | `array<enum>` | 是 | 长度 1–2，取值来自 §6.5 封闭枚举 | 主手法 +（可选）修饰手法；B4 基准 = `BEAT_SYNC_CUT` + `BGM_PITCH_CUT` |
| `locked` | `bool` | 是 | B5 恒为 `true`，其余 `false` | 锁定则不可修改 |
| `stage` | `const` | 是 | 恒为 `POST_COMPOSITE` | 仅后期合成阶段生效 |

**隔离约束：** `transition_rule` 不得被 prompt 组装器读取；组装器输入白名单仅 `emotion`、`duration`、`ai_param.camera_rhythm`、`ai_param.plot_core`（R8、`FR-3-04`）。

### 8.6 Prompt 槽位 ↔ 字段映射

| 槽位序 | 槽位 | 数据来源 | 可编辑 |
| --- | --- | --- | --- |
| 1 | 固定前缀 | 系统常量（方法论维护） | 否 |
| 2 | 本段情绪 | `beat.emotion` | 是（人填） |
| 3 | 时长 | `beat.time_range` 推导的 `duration` | 是（≤30s 内） |
| 4 | 镜头节奏 | `beat.ai_param.camera_rhythm` | 是（人填） |
| 5 | 剧情核心 | `beat.ai_param.plot_core` | 是（人填） |

顺序为 1→5 硬编码，任何模块不得改序（`RULE-8`）。

### 8.7 生成任务（`generate_task`，运行时）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | `id` | 任务主键 |
| `beat_id` | `id` | **1:1 绑定一块板**（`RULE-10`） |
| `prompt_snapshot` | `string` | 提交时的 `prompt_final` |
| `status` | `enum` | `IDLE` / `QUEUED` / `RUNNING` / `SUCCEEDED` / `FAILED` |
| `idempotency_key` | `string` | `beat_id + prompt_snapshot + 入参` 的哈希，用于去重（`FR-4-07`） |
| `error` | `object?` | 失败原因，可解释文案 |

## 9. 非功能需求（NFR）

| 编号 | 需求 | 指标 | 验证方式 |
| --- | --- | --- | --- |
| `NFR-1` | 页面加载 | 三个页面首屏可交互 **≤ 1s**（P95，常规网络） | 前端性能埋点 + 定期基线测试 |
| `NFR-2` | Prompt 组装 | 单板组装耗时 **≤ 200ms**（P95，含转场过滤与校验） | 组装器单测计时 + 线上埋点 |
| `NFR-3` | 生成可靠性 | 生成失败可重试；重复提交幂等，不产生重复任务 | 幂等键用例 |
| `NFR-4` | 数据完整性 | `len(beat_list) == 5`、宫格数匹配、`duration ≤ 30` 三项在后端强校验 | 数据层用例（越过 UI 直调接口） |
| `NFR-5` | 飞书导出 | 一键导出成功；字段含项目名、总时长、5 板规格、prompt、衔接表 | 导出结果字段核对 |
| `NFR-6` | 可解释性 | 所有拦截必须给出可读原因（缺哪个槽位 / 哪块板超时长 / 命中哪个转场词） | 文案评审 |
| `NFR-7` | 术语合规 | 产物文案与字段中无禁用词（禁用词清单文档除外） | 文本扫描检查 |
| `NFR-8` | 自动保存 | 字段失焦到持久化 ≤ 500ms，异常有明确失败态 | 交互用例 |

## 11. 红线与校验映射（Red Line Traceability）

| 红线 | 内容 | 落地机制 | 承接需求 |
| --- | --- | --- | --- |
| R1 | 组内硬切归 AI | 宫格间无任何转场/剪辑点控件 | `FR-5-07`、`FR-2-12` |
| R2 | 组间衔接归人 | 衔接只能人工在封闭枚举内选择，系统不自动决定 | `FR-5-02` |
| R3 | 单板 ≤ 30s | UI 即时报错 + 生成前置拦截 + 后端强校验 | `FR-2-08`、`FR-4-03`、`NFR-4` |
| R4 | 帧序左→右 | 无拖拽/排序控件；`frame.index` 只读 | `FR-2-04`、§8.3 |
| R5 | 5 节拍不可变 | 无增删板入口 + 数据层长度校验 | `FR-1-04`、§8.1 |
| R6 | 无故事板 | 概念级禁止，页面/导出/字段均不出现 | §1.3 D2、`NFR-7` |
| R7 | 宫格数锁定 | 按板序渲染 + 数据层校验 | `FR-1-03`、`FR-2-02` |
| R8 | 转场不进 prompt | 输入白名单 + 组装后转场词扫描 | `FR-3-04`、§8.5 |

硬锁映射：`L1`=R5、`L2`=R6、`L3`=R7+R4、`L4`=R1+R2、`L5`=R3。
