# Seedance 节拍板方法论（Seedance BeatBoard System）

- 文档编号：`METH-001`
- 版本：`v1.0`
- 状态：**CANON / 法条级**（源自官方 PDF 提取的 SOURCE CANON，不可协商）
- 归属：Wave 1 / Slot P1 / Cycle W1 architecture
- 适用范围：全部产品、工程、内容、评审环节

> 本文是本项目的**唯一方法论法源**。任何 PRD、技术方案、UI 稿、Prompt 模板、评审意见若与本文冲突，
> 一律以本文为准；需要变更的部分只能通过修改 SOURCE CANON 并同步本文来完成，不得在下游文档中"就地放宽"。

## 1. 核心公式（Core Formula）

```
1 剧情节拍(Beat) = 1 镜头组(G) = 1 块节拍板(BeatBoard) = Seedance 2.5 单次 generate 单元
```

这条等式是整套体系的地基，含义是四重恒等：

| 层面 | 单位 | 说明 |
| --- | --- | --- |
| 叙事层 | 剧情节拍 Beat | 一次完整的情绪动作（钩子 / 建立 / 升级 / 蓄力 / 断集） |
| 视听层 | 镜头组 G | 一组连续镜头，内部由 AI 自行切分 |
| 生产层 | 节拍板 BeatBoard | 编辑器里的一块板，装 2–3 个节拍帧 |
| 模型层 | 单次 generate | 一块板 = 向 Seedance 2.5 发起的一次生成调用 |

**工程推论（必须落到代码里）：**

1. `beat` 是系统唯一的一等叙事实体，不存在比它更小的可编辑叙事单元。
2. 生成请求与节拍板 **1:1** 绑定；一块板不得拆成多次调用，多块板不得合成一次调用。
3. 数据模型、编辑器、生成队列、成片管理四处的"最小工作单元"必须同为 `beat` / `board`。

## 2. 人机分工（Division of Labor）

**这是全系统的第一红线，任何功能设计都要先回答"这属于人还是属于 AI"。**

| 职责方 | 负责 | 不负责 |
| --- | --- | --- |
| **人（编剧 / 导演）** | 宏观情绪、宏观节奏、**组间衔接（inter-group transition）** | 组内镜头怎么切、切几刀、每刀多长 |
| **AI（Seedance 2.5）** | **组内**运镜、组内剪辑点、组内时长微观分配 | 跨组转场、整集情绪曲线、节拍顺序 |

一句话口诀：**AI 管组内，人管组间（AI intra / human inter）。**

推论：

- 转场（transition）**永远不进 AI prompt**，它是后期合成阶段的人工参数。见 §7。
- 情绪、时长上限、镜头节奏描述**必须进 AI prompt**，因为它们是组内微观决策的约束条件。

---

## 3. 明确废弃项（Discard List）

以下概念在本项目中**不存在**，不得出现在数据模型、UI 文案、API 字段、评审语言中：

| 废弃项 | 原因 | 违规表现（禁止） |
| --- | --- | --- |
| 单镜头 S 拆解（single-shot S breakdown） | 组内切分归 AI | `shot_list`、`S1/S2/S3` 字段或输入框 |
| 分镜 / 故事板（storyboard） | 与节拍板互斥 | "分镜表""故事板"页面、导出格式 |
| 单镜时长（per-shot duration） | 时长微观分配归 AI | 每个镜头一个 duration 输入框 |
| 手动逐镜转场（manual per-shot transitions） | 转场只在组间由人工设定 | 组内相邻镜头之间的转场下拉框 |

**判定规则：** 只要一个字段/控件的粒度小于 `beat`，它就是废弃项，直接删除，不做"隐藏"或"高级选项"处理。

## 4. 五节拍锁（5-Beat Lock）

一集 = **恒定 5 块节拍板**，顺序与语义写死，不可增删、不可换序、不可改名：

| # | 节拍名 | 英文 | 叙事任务 |
| --- | --- | --- | --- |
| Beat 1 | 开篇钩子 | Opening Hook | 3 秒内抓住观众，制造冲击 |
| Beat 2 | 矛盾建立 | Conflict Setup | 明确对立面与利害关系 |
| Beat 3 | 打压升级 | Escalation / Suppression | 主角被持续打压，压力见顶 |
| Beat 4 | 反转蓄力 | Reversal Charge-up | 势能积累，反转前的临界点 |
| Beat 5 | 断集留客 | Cliffhanger Cut | 在最高势能处切断，留住观众 |

**整集时长：70–90 秒。**

> 时长口径说明：本文 §6 的分镜位表（Beat1 0–8s … Beat5 70–88s）是官方样板的**基准时间轴**，
> 总长 88s，落在 70–90s 区间内。允许在 70–90s 内整体伸缩，但**节拍数量恒为 5、顺序恒定**。

## 5. 标准工作流（Workflow）

```
定节拍 → 定镜头组 → 填节拍帧 → AI 生成 → 后期合成
```

| 阶段 | 中文 | 执行方 | 产出 | 关键约束 |
| --- | --- | --- | --- | --- |
| 1 | 定节拍 | 人 | 5 个 beat 的情绪与剧情核心 | 只能是 5 个，语义按 §4 |
| 2 | 定镜头组 | 人 | G1–G5 与各组时间位、时长 | 单板时长 ≤ 30s |
| 3 | 填节拍帧 | 人 | 每板 3 帧（B5 为 2 帧） | 帧序**只按左→右**，不可重排 |
| 4 | AI 生成 | AI | 每板一段视频 | 一板一次 generate；prompt 无转场 |
| 5 | 后期合成 | 人 | 成片 | 组间衔接方式由人工在此阶段应用 |

阶段 3 与阶段 4 之间是 **Prompt 组装** 环节（见 §7），阶段 4 与阶段 5 之间是 **组间衔接管理**（见 §8）。

## 6. 节拍板基准表（Golden Board Spec）

| 板 | 节拍 | 镜头组 | 时间位 | 时长 | 节拍帧数 | 帧语义 | 组间衔接（本板→下一板） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| B1 | 开篇钩子 | G1 | 0–8s | 8s | **3** | 冲击 / 反应 / 环境（impact / reaction / env） | **音频预接** |
| B2 | 矛盾建立 | G2 | 8–25s | 17s | **3** | 三帧递进 | **卡点硬切** |
| B3 | 打压升级 | G3 | 25–45s | 20s | **3** | 三帧递进 | **纯硬切** |
| B4 | 反转蓄力 | G4 | 45–70s | 25s | **3** | 三帧递进 | **卡点硬切 + BGM 升调** |
| B5 | 断集留客 | G5 | 70–88s | 18s | **2** | 两帧收束 | **无转场，黑屏截断** |

要点：

- **B1–B4 为三宫格，B5 为两宫格**，这是 UI 与数据结构的硬约束（PRD P0 同步锁定）。
- 每板时长必须 **≤ 30s**（当前最大值 B4 = 25s，留有余量但上限不可突破）。
- "组间衔接"一列描述的是**本板结束到下一板开始**的人工处理；B5 的衔接指向"集与集之间"，为黑屏截断。

完整样板内容（含每帧文案与逐板 prompt）见 [`golden-5-beats.md`](./golden-5-beats.md)。

## 7. Prompt 组装法（Prompt Assembly）

### 7.1 固定前缀（Fixed Prefix）

```
漫剧厚涂画风，高清8K... 人物五官稳定无漂移...
```

固定前缀由系统注入，**用户不可编辑、不可删除**；它承担画风统一与角色一致性（防五官漂移）两项职责。

> 前缀中的 `...` 为源稿省略号，表示该处存在受控扩展位。扩展只能由方法论层统一维护，
> 不得由单个项目/单块板私自改写。

### 7.2 组装公式

```
固定前缀 + 本段情绪 + 时长 + 镜头节奏 + 剧情核心
```

| 槽位 | 来源 | 是否必填 | 备注 |
| --- | --- | --- | --- |
| 固定前缀 | 系统常量 | 是 | 只读 |
| 本段情绪 | beat 字段 | 是 | 宏观情绪，由人填写 |
| 时长 | beat 字段 | 是 | ≤ 30s |
| 镜头节奏 | beat 字段 | 是 | 只描述节奏感，不写具体几刀 |
| 剧情核心 | beat 字段 | 是 | 一句话剧情推进 |

### 7.3 Prompt 红线

- **转场描述绝不进入 AI prompt**（Transitions NEVER in AI prompt）。
- 不写"第 1 个镜头 3 秒、第 2 个镜头 2 秒"这类逐镜指令——那是废弃项 §3。
- 不写具体剪辑刀数；只给节奏形容（如"快切递进""渐压迫感"）。
- 槽位顺序固定，组装器不得改序，便于模型稳定响应。

## 8. 组间衔接管理器（Inter-group Transition Manager）

人工可选的衔接手法，**共 5 种，枚举封闭**：

| 手法 | 典型用法 | 出现位置（基准表） |
| --- | --- | --- |
| 音频预接 | 下一段音频提前进入，听觉先行 | B1 → B2 |
| 螺口顺滑 | 画面元素咬合式顺滑过渡 | 可选 |
| 卡点硬切 | 踩音乐点的硬切 | B2 → B3、B4 → B5 |
| BGM 升调截断 | 升调推动情绪，配合硬切 | B4 → B5（与卡点硬切叠加） |
| 黑屏断钩子 | 黑屏截断，留悬念 | B5 集尾 |

规则：

1. 衔接值挂在**上一块板**上，语义为"本板结束时如何进入下一板"。
2. 衔接**只在后期合成阶段生效**，不影响生成调用。
3. B5 的衔接固定为"无转场 / 黑屏截断"，不可改。
4. 组内不存在人工转场；组内硬切由 AI 自行产生（见 §9 红线 1）。

## 9. 红线清单（Red Lines）

| # | 红线 | 判定 | 违规后果 |
| --- | --- | --- | --- |
| R1 | 组内硬切由 AI 负责（intra-group AI hard cuts） | 组内出现人工剪辑点/转场控件即违规 | 方案打回 |
| R2 | 组间衔接由人负责（inter-group human transitions） | 系统自动决定组间转场即违规 | 方案打回 |
| R3 | 单板时长 ≤ 30s | 任何板 duration > 30 即违规 | 生成拦截 |
| R4 | 节拍帧只按左→右顺序（frames L→R order only） | 出现拖拽重排、乱序提交即违规 | UI 打回 |
| R5 | 5 节拍不可变（5 beats immutable） | 增删板、改序、改语义即违规 | 数据层拦截 |
| R6 | 无分镜 / 故事板 | 出现 storyboard 概念即违规 | 需求打回 |
| R7 | 宫格数锁定（B1–B4 = 3，B5 = 2） | 宫格数可变即违规 | UI + 数据层拦截 |
| R8 | 转场不进 prompt | 组装后的 prompt 含转场词即违规 | 组装器拦截 |

**校验建议：** R3、R5、R7、R8 可做成自动校验（后端 + 组装器双重）；R1、R2、R4、R6 通过 UI 形态与评审清单保障。

## 10. PRD 对齐要点（PRD Highlights）

### 10.1 P0 功能范围

1. **五节拍模板库**（5-beat template library）
2. **可视化节拍编辑器**：B1–B4 三宫格、B5 两宫格
3. **Prompt 组装器**（Prompt assembler）：按 §7.2 公式拼装
4. **Seedance 生成**：单次 ≤ 30s
5. **组间衔接管理器**：音频预接 / 螺口顺滑 / 卡点硬切 / BGM 升调截断 / 黑屏断钩子

### 10.2 UI 约束

- 布局：**左侧导航 + 顶部栏 + 主编辑区**。
- 页面：**项目列表 / 核心编辑器 / 成片管理**（三页，不多不少）。
- **禁止出现**：分镜、故事板、单镜时长 任何输入项。

### 10.3 数据约束

- 项目级：`project_id`、`name`、`total_duration`、`beat_list[5]`。
- `beat_list` 长度恒为 **5**；beat 内部字段以 **PRD §8** 为准（本文不复制其字段清单，避免双源）。

### 10.4 硬锁（Hard Locks）

| 锁 | 内容 |
| --- | --- |
| L1 | 5 beats immutable |
| L2 | no storyboard |
| L3 | grid order locked |
| L4 | AI intra / human inter |
| L5 | 30s cap |

## 11. 一致性检查清单（Review Checklist）

评审任何下游产物时，逐条打勾：

- [ ] 最小可编辑叙事单元是 beat，没有更小粒度字段？
- [ ] beat 数量恒为 5，语义与顺序与 §4 一致？
- [ ] B1–B4 三宫格、B5 两宫格？
- [ ] 帧顺序只允许左→右，无重排入口？
- [ ] 每板时长 ≤ 30s，且有自动拦截？
- [ ] 生成调用与板 1:1？
- [ ] prompt = 固定前缀 + 情绪 + 时长 + 镜头节奏 + 剧情核心，顺序未变？
- [ ] prompt 中不含任何转场描述？
- [ ] 组间衔接是人工设置，且取值在 5 种枚举内？
- [ ] 全文无"分镜 / 故事板 / 单镜时长"字样？
