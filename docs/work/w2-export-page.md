## 2. 五张段卡与卡序锁（PRD 5.5.1 / AC-6.7）

卡序不是「渲染时排一下序」，而是**结构上不可能错**：`buildSegmentCards` 只按
`BEAT_INDEXES` 遍历 `project.beat_list`，生成状态数组仅作为按 `beat_index` 查表的数据源。
于是三种脏输入都改不动卡序，测试逐条覆盖：

| 脏输入 | 结果 |
| --- | --- |
| 状态数组整体倒序 | 仍是 1 → 5，五张卡内容正确 |
| 状态数组缺项 | 缺的板回落到「待生成」空白卡，**不少一张卡** |
| 状态数组有重复项 | 按板序取第一个匹配，不错位、不多卡 |

返回的数组与每张卡都 `Object.freeze`，`reverse()` 与字段赋值直接抛 `TypeError`——
段卡是只读视图模型，改它既改不动板，也进不了任何请求体。

一张卡上的元素顺序对齐 §11.4 线框：

```
预览占位 → 节拍序号·名称 + 状态徽章 → 时长 → 生成完成时间 → 组间衔接
        → [下载本段] [重新生成] [去编辑]
```

- **预览占位**：V1.0 不内嵌播放器。桩件地址是 `stub://`，`<video>` 放上去只会是个坏元素，
  所以四态各给一句占位文案（未生成 / 生成中… / ▶ 预览占位 / 生成失败），
  真实签名 URL 接上后把这一块换成播放器即可，其余不动。
- **生成完成时间**：取任务成功时的 `updated_at`，按 **UTC** 定长格式化成
  `2026-08-27 09:12:00 UTC`。没用 `toLocaleString`——它会让同一份代码在不同机器上出不同文案，
  测试也就没法钉死。
- **下载**：命名恒为 `项目名_节拍序号_节拍名.mp4`（PRD 5.5.2）。文件名里的项目名与节拍名
  经过净化（路径分隔符与 Windows 保留字符换下划线），中文原样保留，后期合成的人一眼能对上板。
- **重投闸门**：只有「生成过且当前不在途」的段给重投入口；没生成过的段只给「去编辑」，
  在途的段提示等这一轮跑完。禁用一律带可读原因（IX-3）。

## 3. 组间衔接：卡上可见，请求体里不可见（R2 / AC-6.4）

成片页是衔接**唯一该被看见**的地方——后期合成要照着它剪。所以本槽位同时下了两面断言：

| 位置 | 有没有衔接 |
| --- | --- |
| 段卡「组间衔接」一栏 | 有，且标注「仅后期合成生效，不进生成」 |
| 底部衔接总表（5 行） | 有，含枚举码、生效阶段、说明 |
| 拼接计划「出段后衔接」列 | 有 |
| 项目 JSON 的 `beats[].transition_rule` | 有 |
| 各板 `prompt_final` | **没有** |
| 传输层实际收到的请求体 | **没有** |

第六行是本槽位最硬的一条：测试用一个**记录式传输层**把请求体原样收下来，再断言
六种衔接取值、名称哨兵、备注哨兵一个字都不在体内。页面上点「重新生成」走的是
`controller.retryBeat`，请求体由 `domain/prompt.ts` 的白名单组装——
成片页压根没有写回生成侧的通路，这不是「记得过滤」，而是没有那条路。

衔接语义沿用 W1/WK2 的口径：挂在上一块板，末板指向 `下一集`（本产品没有第 6 块板），
所以总表恒 5 行：`节拍1 → 节拍2` … `节拍5 → 下一集`。

## 4. 底部三块

### 4.1 拼接计划

V1.1「一键拼接」的输入契约先行版，5 行恒定：

| 段 | 时间位 | 时长 | 状态 | 出段后衔接 | 取件地址 |
| --- | --- | --- | --- | --- | --- |
| 节拍1·开篇钩子 | 00:00 – 00:08 | 8 秒 | 成功 | 节拍1 → 节拍2：音频预接 | `stub://…` |

时间位由**板时长累加**得出，不是抄 canon 时间位：板时长改了，起止位随之重算
（测试覆盖 B1 改 8 → 6 秒后五行全体前移）。合计行给总时长与「已齐 n/5 段」，
缺片时点名缺哪几段；整集时长跌出 70–90s 区间时补一条提示，但**不阻断**导出。

### 4.2 组间衔接总表

`FR-5-06` 的落点，与段卡同源（`plan.transitions[i] === cards[i].transition`，测试用引用相等钉死）。
五列：衔接点 / 手法 / 枚举码 / 生效阶段 / 说明。表尾复述 AC-6.4 的口径。

### 4.3 项目导出与交付包

| 出口 | 何时可用 | 内容 |
| --- | --- | --- |
| 导出项目 JSON | 随时 | 版本号 + 导出时间 + 项目级字段 + 5 板全字段（含宫格、衔接、备注）+ 各板 `prompt_final` + 衔接总表 + 拼接计划 |
| 导出交付包清单 / 顶栏「全部下载」 | 5 段齐备 | zip 名、zip 内路径、每项取件地址、缺片板号、打包说明 |

**为什么清单不是二进制 zip**：V1.0 的视频地址是桩件地址，拿不到字节流，
硬打一个只有文本的 zip 只会误导后期合成的人以为文件丢了。所以先出清单——
`entries` 里写清「zip 内路径 ← 取件地址」，`note` 里如实写明桩件地址尚不可抓取。
接真实签名 URL 后按清单逐项抓取打包即可，**清单结构不用改**。

导出动作走可注入的 `FileDownloader`（默认 Blob + `<a download>`，jsdom 等不支持的环境回落空实现）。
以后改成「请求服务端出包、返回签名 URL」也只换这一个函数，组件不动。

## 5. 版本纪律：一键拼接留位（PRD 5.5.5 / §10）

顶栏「一键拼接（V1.1）」按钮**置灰**，`title` 写明「一键拼接为 V1.1 能力，V1.0 只出拼接计划」。
V1.0 不为 V1.1 预埋任何可用功能，唯一允许的占位就是这个按钮位。

与其做半个假连播，不如把禁用原因写清楚。

## 6. 取舍与留痕

1. **不碰在途槽位的地盘。** 页面本体全在 `apps/web/src/export/**`；`routes/ExportPage.tsx`
   只剩 20 行的取项目 + 兜底；样式独立在 `export/export.css`（由 `ExportView` 自行引入），
   **没有改 `styles.css`**，也没有动 `generate/` 与 `domain/` 的任何文件。
   与 integrate / store 槽位的冲突面收敛到「路由文件那 20 行」。
2. **不重写 `assemblePrompt` 与禁用词扫描器。** 本槽位只调用，不改锁。
3. **复用既有类名。** 段卡沿用 `.segment*`，状态徽章沿用 `.generate__badge*`，
   `<li className="segment">` 原样保留——W1/WK1 的 `App.test.tsx` 用它数 5 张卡，
   守卫测试一条没删、一条没改。
4. **重投走二次确认**（PRD 12.6）。用卡内内联确认而不是 `window.confirm`：
   前者可测、可无障碍标注，后者在 jsdom 里只能打桩。
5. **缺片不阻断项目 JSON 导出。** 缺片只锁交付包（那是要交出去的东西），
   档案导出属于随时可做的动作。
6. **没有剪辑概念**（R7）。页面文案与 DOM 里都不存在轨道 / 裁剪 / 时间线，
   测试有一条正则专门守这个，同时守「增删段卡 / 改序」入口不存在。
