## 2. 五板导航：键盘可达

### 2.1 为什么不做 roving tabindex

标准的 tablist 模式是「整组只占一个 Tab 位，进组后用方向键」。这里**没有**采用，
因为 5 块板不是"一个控件的几个取值"，而是 5 个并列的作业入口——
用户脑子里的模型是"第 3 板"，不是"节拍选择器的第 3 档"。

所以 5 个 `<button>` 全部留在自然 Tab 序里（逐项 Tab 可达，符合 2.1.1），
方向键 / Home / End 只是**额外**的快捷键，不替代 Tab：

| 按键 | 行为 |
|---|---|
| `Tab` / `Shift+Tab` | 逐板前后移动，顺序即板序 B1→B5 |
| `↓` / `→` | 下一板；在 B5 回环到 B1 |
| `↑` / `←` | 上一板；在 B1 回环到 B5 |
| `Home` / `End` | 直达 B1 / B5 |
| `Enter` / `Space` | 切板（`<button>` 默认语义，未被 `onKeyDown` 截走） |

方向键**移动焦点的同时切板**。不做"焦点在 B3、内容还停在 B1"的中间态：
左导航点哪块板就看哪块板，键盘不该有另一套规则。上下与左右等价——
导航虽是一列，但方向键不该挑剔轴向。

### 2.2 aria-current

当前板标 `aria-current="step"`，非 `"true"`。五板是一条固定推进的叙事序列
（METH-003 §1 的时间位 0-8 / 8-25 / 25-45 / 45-70 / 70-88 就是这条序列的刻度），
`step` 恰是这个语义。测试断言全页**恰有一个** `aria-current`，且指向当前板——
"高亮了两块板"或"高亮跟不上内容"都会立刻红。

### 2.3 状态点不只靠颜色

板状态（未填 / 已填 / 生成中 / 已生成 / 失败）原本只由一颗色点承载，
色觉障碍用户读不到（WCAG 1.4.1）。现在：hover 给 `title`，无障碍树给隐藏文本，
按钮的无障碍名因此形如「3 开篇钩子 … 已填」。测试逐板断言名字里能匹配到状态词。

## 3. 宫格：逐格唯一命名

原来一板里 2–3 个格的文本域，可见标签一律是「画面描述」，
无障碍名也就一模一样。屏幕阅读器用户连续听到三个「画面描述」，
等于被告知"随便填一个"——而格序**就是时序**（帧序锁，左→右），填错格即叙事错位。

现在每个宫格控件都带格序，用术语表 §1 的标准词**「节拍帧」**而非口语的「格」：

| 控件 | 无障碍名 |
|---|---|
| 画面描述文本域 | `节拍帧1 画面描述` / `节拍帧2 画面描述` / `节拍帧3 画面描述` |
| 参考图选择按钮 | `为节拍帧1选择参考图` |
| 参考图 file input | `节拍帧1 参考图` |
| 移除参考图按钮 | `移除节拍帧1的参考图` |

可见标签「画面描述」是无障碍名的**子串**，满足 WCAG 2.5.3（Label in Name）——
语音控制用户说"画面描述"仍能命中。测试对此单列一条断言。

宫格列表项（`<li>`）由 `aria-labelledby` 指向卡头，因此按列表导航时报的是「格 1 冲击」，
而不是一串无名条目。

### 3.1 视觉隐藏的 file input 退出 Tab 序

`<input type="file" class="visually-hidden">` 虽然看不见，却仍然可 Tab。
一板 3 格就是 3 个"看不见的焦点站"，全集 14 个，而且它和上面那颗可见按钮
触发的是同一件事。现在它降为 `tabIndex={-1}` 的纯机制，键盘入口只留可见按钮。
测试断言这三个 input 确实不出现在 Tab 序里——这条断言同时防止将来有人把它加回去。

参考图已挂载时，可见入口变为「移除参考图」；键盘更换参考图的路径是"先移除再选择"，
两步，均可达。

## 4. 焦点顺序：信息条 → 宫格左→右 → 组间衔接 → Prompt 预览

焦点顺序即作业顺序（WCAG 2.4.3）。编辑页主区的 Tab 序：

```
情绪基调 → 本拍时长          ← 信息条（板名 / 时间位 / 画幅只读，不占焦点）
  → 剧情核心 → 镜头节奏
  → [节拍帧1 参考图 → 节拍帧1 描述]
  → [节拍帧2 参考图 → 节拍帧2 描述]   ← 宫格，严格左→右
  → [节拍帧3 参考图 → 节拍帧3 描述]
  → 衔接手法（单选组占 1 位，组内方向键） → 操作要点   ← complementary
  → （Prompt 预览无可操作控件）                        ← complementary
```

宫格段的顺序不是排版的副产品，而是**帧序锁在键盘上的样子**：测试取三个描述框
在 Tab 序中的位次，断言严格递增。

Prompt 预览里没有可聚焦控件（它是纯输出面板），Tab 序校不到，
因此另用 `compareDocumentPosition` 校四个区块的 DOM 顺序——朗读顺序与视觉顺序一致。

### 4.1 衔接与预览是 complementary

`TransitionPanel` 由 `<section>` 改为 `<aside>`，与 Prompt 预览一样成为
complementary 地标。这不是排版选择，是 AC-6.4 那条红线的听觉版本：
**衔接是后期合成的旁支信息，不参与 AI 生成，与「这一板要生成什么」不在同一条主线上。**
屏幕阅读器的地标列表因此把它列在主内容之外，和预览并列。

测试断言主区内恰有两个 complementary，名字依次是「组间衔接」「Prompt 预览」。
既有的 `getByRole('region', { name: '组间衔接' })` 随之更新为 `getByRole('complementary', …)`
——同一断言换角色名，判定强度不变。

B5 无接缝时地标仍在，内容改为「本集不设衔接」，且组内 0 个单选钮。

### 4.2 Prompt 预览的两处修补

- `<div aria-label="Prompt 全文">` 是个只挂了标签的裸 `div`：generic 角色不进无障碍树，
  这个名字实际上没人听得到。补 `role="group"` 后它才是一个具名区块。
- 「就绪 / 待补全」是编辑过程中唯一会自己变化的**判定结论**，加 `role="status"` 播报，
  键盘用户不必反复 Tab 回预览面板确认。Prompt 全文本身**不**播报——
  每敲一个字都念一遍全文是噪音，不是无障碍。

## 5. 信息条：只读值脱离 `<output>`

只读字段（板名 / 时间位 / 画幅 / 参考图数）原本用 `<output>` 承载。
`<output>` 的隐含角色是 `status`，自带 `aria-live="polite"`——
切板时这四个只读值会各自抢播一遍，把「切到了哪一板」这条真正重要的信息淹掉。
它们只是规格展示，不是运算结果，语义上本来也不该是 `<output>`。

现在改为 `<span>`，并给每个字段容器 `role="group"` + `aria-labelledby` 指向自己的标签：
「板名 / 开篇钩子」这对关系因此是程序可读的，而不只是视觉上的上下相邻。

顺带的收益：全页 `role="status"` 恢复唯一（就是预览面板那枚徽标），
`getByRole('status')` 不再命中一堆只读值。

**红线未受影响**：板名仍是只读呈现 + 「锁定」标记，不是被禁用的输入框，是**没有**输入框。
既有的「板名只读」断言（扫描所有 textbox / combobox / spinbutton 的 value）原样通过。

## 6. 跳转链接与焦点可见性

### 6.1 跳到主内容

编辑页在主区之前有顶部栏和 5 项左导航；没有跳转链接，键盘用户每次进页面都要
先 Tab 过 7 个落点才摸到第一个输入框（WCAG 2.4.1）。现在 Tab 第一站是「跳到主内容」，
平时收在视口外，拿到焦点才落下来。

`<main>` 带 `tabIndex={-1}` 承接焦点，链接另挂一次显式 `focus()`——
只靠 `href="#id"` 在部分浏览器里只滚动、不移焦点，跳过去之后按 Tab 又弹回导航，
那这个链接等于没有。

### 6.2 焦点环

基线 CSS 里只有 `.input:focus-visible { outline: none; border-color: var(--accent) }`：
输入框把系统焦点环删了、换成一道 1px 边框色变化；按钮、链接、导航项则**完全没有**焦点样式。
在这种深色密排界面里，靠 hover 态那点背景差是看不出焦点在哪的。

现在统一一道 2px 亮环，新增 `--focus: #7fb2e0`：

| 环色对背景 | 对比度 | 要求（1.4.11 非文本对比度） |
|---|---|---|
| `--bg` `#101216` | 8.4 : 1 | ≥ 3 : 1 |
| `--bg-elev` `#16191f` | 7.9 : 1 | ≥ 3 : 1 |
| `--bg-elev-2` `#1c2027` | 7.3 : 1 | ≥ 3 : 1 |
| `--bg-inset` `#0b0d11` | 8.7 : 1 | ≥ 3 : 1 |

跳转链接自身用 `--accent-ink` on `--accent`，4.97 : 1，过 AA 正文阈值。

用 `:focus-visible` 而非 `:focus`，鼠标点击不留描边——工业界面的克制感不受影响。

两处需要特殊处理，都是"环画不出来"的情况：

- **衔接手法卡片**：单选钮本体是 `visually-hidden` 的 1px 元素，环画在它上面等于没画。
  改由 `.template:focus-within` 在整张卡片上代画，否则键盘选衔接手法是盲选。
- **参考图投放区**：`.dropzone` 带 `overflow: hidden`，会裁掉子元素外扩的 outline。
  触发按钮与移除按钮改用 `outline-offset: -2px` 画在内侧。

## 7. 全站扫描：主区无匿名控件

光修已知的几处不够——需要一条能拦住**将来**新增控件的断言。
测试用 `dom-accessibility-api` 的 `computeAccessibleName` 逐板扫描主区里所有
`a[href] / button / input / select / textarea`，任何一个算出空名就报出它的 outerHTML 片段。
左导航与顶部栏另有一条同样的扫描。

再加一条：主区所有 `textarea / select / input[type=number]` 的名字**两两不重名**——
这正是第 3 节那个"三个画面描述"问题的通用形式，任何人将来复制一个同名字段都会立刻红。

`dom-accessibility-api` 原本只是 `@testing-library/dom` 的传递依赖，
本槽位把它提到 `devDependencies` 显式声明（`^0.7.1`），避免依赖树变化时静默失效。
