## 2. 为什么不复用项目 JSON

W2/EXPORT 已经有 `export/projectExport.ts` 的项目 JSON 了，本槽位没有改它，
而是并列出了第二种产物。分工是清楚的：

| 产物 | 读者 | 形态 | 何时用 |
| --- | --- | --- | --- |
| 项目 JSON（W2） | 导入侧程序 | 全字段、嵌套三层、可回灌 | 备份、迁移、快照可溯（AC-6.9） |
| 飞书文档（W4） | 后期合成 / 编剧 / 评审 | 分节、可粘贴、Markdown 与 JSON 双形态 | 评审、派单、走审批流 |

把项目 JSON 直接贴进飞书文档，得到的是一坨没人读的代码块——
`stitch_plan.rows[3].transition.point_label` 这种路径对程序友好，对人不友好。
飞书文档反过来：字段做了取舍（不带幂等键、不带任务 ID），排版做了分节，
表格列数控制在 6 列以内，一屏能看完一节。

两份产物**共用同一个 Prompt 组装器**（`domain/prompt.ts`），所以「所见即所发」在两边逐字一致，
不存在「导出 A 和导出 B 的 Prompt 不一样」这种事。

## 3. 五拍在文档里的落点（R3 / AC-6.7）

段序不是「渲染时排一下序」：`buildFeishuDoc` 只按 `BEAT_INDEXES` 遍历 `project.beat_list`，
`options.cards` 仅作为按 `beat_index` 查表的状态来源。于是脏输入改不动段序，测试逐条覆盖：

| 脏输入 | 结果 |
| --- | --- |
| 段状态数组整体倒序 | 仍是 1 → 5，各节的表与段落顺序不动 |
| 段状态数组缺项 | 该段状态留破折号，**段数不少一段** |
| 完全不给段状态 | 不出「成片交付状态」一节，其余五节照出（编辑阶段也能导） |

每一段带的字段：

```
情绪 · 时间位（canon 0-8s…）· 板时长 · 镜头节奏 · 剧情核心 · 节拍帧（左 → 右）· 备注
                                                                    ↑
                                              节拍 1 的三格带 canon 语义标注：冲击 / 反应 / 环境
```

Prompt 全文与组间衔接**不在这一段里**，各自成节——理由见下一节。

`5` 这个数在四处同时被数：总览表 5 行、明细 5 段、Prompt 5 段、衔接总表 5 行。
测试对四处分别计数，任何一处漏一段都会变红。

## 4. 分节即契约：衔接只在后期那一节（AC-6.4）

文档恒为六节，节名就是二级标题文案（`FEISHU_SECTIONS`）：

```
项目信息 → 五节拍总览 → 节拍明细 → Prompt 全文（所见即所发）
        → 组间衔接总表（后期合成） →（成片交付状态）
```

分节不只是排版，它是红线在本槽位的**可检验形式**：

| 一节 | 有没有衔接 |
| --- | --- |
| 组间衔接总表（后期合成） | 有，5 行，逐行带枚举码与生效阶段「后期合成」 |
| Prompt 全文 | **没有**，连「后期」「衔接」两个词都不出现 |
| 节拍明细 | **没有**，只讲画面 |
| 项目信息 / 五节拍总览 / 成片交付状态 | **没有** |

「后期」这个标签出现在三处，读者不必翻到表尾才知道衔接的适用范围：
节标题里（`组间衔接总表（后期合成）`）、节首的引用块里、表格的「生效阶段」列里各一处。

**断言方式是本槽位最要紧的一处设计。** `splitMarkdownSections` 把渲染结果按二级标题切开，
测试逐节复查，而不是对整篇文本做一次模糊匹配——后者会把「衔接总表里本该有衔接」
和「Prompt 里不该有衔接」混成一句话，等于什么都没守住。切分器认二级标题、
跳过代码块内部的 `#`，所以 Prompt 正文里出现 `## ` 也切不错节（测试有一条专门造这个输入）。

顺带守住的还有：**衔接的四个表头**（衔接点 / 手法 / 枚举码 / 生效阶段）也只在后期那一节，
以后谁想在明细里补一列衔接，这条会先红。

衔接语义沿用 W1/WK2 与 W2/EXPORT 的口径——挂在上一块板、末拍指向 `下一集`——
`point_label` 直接复用 `export/segments.ts` 的 `buildSegmentTransition`，
不在本槽位重造一套标签，免得两处文案漂移。

## 5. 复制与下载

| 动作 | 产物 | 用途 |
| --- | --- | --- |
| 复制飞书 Markdown | 剪贴板纯文本 | 直接粘进飞书文档，标题 / 表格 / 代码块自动成形 |
| 下载 Markdown | `项目名_节拍板_飞书.md` | 存档、走审批流、丢进 IM |
| 下载飞书 JSON | `项目名_节拍板_飞书.json` | 给飞书多维表格 / 自动化脚本吃 |

- **只写纯文本**，不写 `text/html`。飞书粘贴 Markdown 文本时会自行解析成块级元素；
  写 HTML 反而会把代码块里的 Prompt 全文变成富文本，复制出去就不是「所见即所发」了。
- **复制走可注入实现**（`ClipboardWriter`），和 W2 的 `FileDownloader` 一个套路。
  `navigator.clipboard` 在 jsdom 里不存在、在非安全上下文里会被浏览器拒绝——
  这两种失败都必须变成页面上一句可读的话，不能是控制台里的一条红字（IX-3）。
  不支持时按钮**不禁用**：点下去给「请展开下方预览手动全选复制」，比一个灰按钮有用。
- **文件名复用** `export/naming.ts` 的 `sanitizeFileNamePart`：路径分隔符与 Windows
  保留字符换下划线，中文原样保留，与逐段视频命名同一套净化规则。
- **缺片不阻断**。三个出口在缺片时全部可用，只是「成片交付状态」一节会点名缺哪几段。
  缺片只锁交付包（那是要交出去的东西），评审与档案属于随时可做的动作。

Markdown 只用飞书粘贴支持的五种块级元素（标题、表格、列表、引用、代码块），
不用 HTML、不用嵌套表格。表格单元格里的 `|` 转义、换行压成空格、空值给破折号——
飞书把空单元格读成「漏填」，破折号是「确实没有」。
Prompt 全文放在代码围栏里，围栏长度按内容加长（`fenceFor`），
用户在剧情核心里写了三个反引号也截不断文档。

## 6. 取舍与留痕

1. **新目录 `share/`，与在途槽位零冲突。** 载荷、渲染器、剪贴板、面板、样式全在
   `apps/web/src/share/**`；对 `export/**` 的改动收敛到 `ExportView.tsx` 里
   「多一个面板 + 多一个注入口」的 19 行（含注释与形参改多行），
   `export/` 下除测试外其他文件一个字没动。
   `styles.css`、`domain/`、`generate/` 全未触碰。
2. **依赖方向单一：`share/` → `export/` → `domain/`。** 本槽位只读
   `export/segments.ts`（衔接标签）、`export/naming.ts`（文件名净化）、
   `export/download.ts`（`DownloadFile` 类型），没有反向依赖，也没有引入循环。
3. **不改 `assemblePrompt`、不改禁用词扫描器、不改项目 JSON。** 只调用，不改锁。
4. **文档段数不可配。** 出口里没有「导出前 N 拍」「跳过某拍」这类参数，
   段数由 `BEAT_INDEXES` 决定。`share/index.ts` 的注释写明了这条以及另两条不得新增的能力。
5. **预览默认折叠。** 面板里放了 `<details>` 折叠的 Markdown 预览：一是让人在复制前
   看一眼要粘什么，二是剪贴板不可用时的手动兜底。折叠是因为它有几十行，
   展开会把底部四块顶得很长。
6. **时间戳取两次。** 预览用的那一份带固定时间戳，重新渲染不会让预览文本抖动；
   点击导出时另取一次，保证文件里的时间是点击那一刻。
7. **没有回写通路。** 面板读 `project` 与段状态、产出文本，仅此而已。
   它不组装生成请求体，也没有按导出结果改节拍的入口。

## 7. 交给下一槽位

1. **接飞书开放平台**：`buildFeishuDoc` 的返回值即字段集，`schema_version` 已就位，
   字段全 snake_case。要推飞书云文档就把 `renderFeishuMarkdown` 的输出丢进
   「导入为文档」接口；要推多维表格就直接吃 `doc.beats`（每段一行，
   `transition` 单独一列并保留 `stage` 字段）。
2. **接飞书机器人推送**：`buildFeishuExport` 一次给出载荷、正文与两个文件，
   面板不必参与；定时推送或生成完成即推都只需要这一个函数。
3. **接真实持久化 / 真实成片地址**：面板通过 `cards` 吃段状态，
   换 `GenerateJobStore` 实现或换真实签名 URL 都不用动本槽位。
4. **要加节请先想清楚衔接落在哪一节。** 新增一节时把节名加进 `FEISHU_SECTIONS`，
   `feishuMarkdown.test.ts` 里「衔接只在后期那一节」的两条断言会自动把新节纳入检查范围
   （它们遍历的是「除后期那一节以外的全部节」）——**这是有意的**，不要为了让测试变绿
   而把新节从遍历里排除。
5. 新增文案前先跑 `npm run lint:terms`；面板与 Markdown 文案都属于产品源码，**不得开例外**。
